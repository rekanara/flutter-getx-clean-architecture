# Firebase Services

Location: `lib/config/firebase/`

## File Structure

| File | Function |
|---|---|
| `firebase_service.dart` | Firebase Core initialization |
| `firebase_options.dart` | Platform-specific config (generated by FlutterFire CLI) |
| `firebase_messaging_service.dart` | FCM: push notification, token management |
| `remote_config_service.dart` | Remote Config: maintenance mode, feature flags |

---

## 1. Firebase Core (`FirebaseService`)

Singleton static class — call once in `main.dart`:

```dart
await FirebaseService.init();
```

Automatically reads `DefaultFirebaseOptions.currentPlatform` generated by the FlutterFire CLI.

---

## 2. Firebase Messaging (`FirebaseMessagingService`)

Permanent GetX singleton that manages **FCM (push notification)**.

### Initialization

```dart
final fcm = Get.put(FirebaseMessagingService(), permanent: true);
await fcm.init();
```

### Features

- **Permission request** (iOS) — automatic in `init()`
- **Token management** — observable `fcmToken`, auto-refresh
- **APNs token** — for iOS
- **Foreground/Background/Terminated messages**
- **Topic subscribe/unsubscribe**
- **Routing based on `type`** from JSON payload

### Usage

```dart
final fcm = Get.find<FirebaseMessagingService>();

// Read token
print(fcm.fcmToken.value); // send to backend

// Subscribe to a topic
fcm.subscribeToTopic('promo');
fcm.unsubscribeFromTopic('promo');

// Force refresh token
final newToken = await fcm.refreshToken();
```

### Incoming Notification Flow

```
Push Notification Received
    │
    ├─ Foreground  → _processMessage() → ShowNotificationHelper
    ├─ Background  → firebaseMessagingBackgroundHandler (top-level)
    └─ Terminated  → _checkInitialMessage() → _handleNotificationTap()
    
_processMessage():
    1. Parse title, body from message.notification
    2. Parse JSON from message.data
    3. Get "type" field → _parseNotificationType()
    4. Call ShowNotificationHelper.showNotification()
```

### Expected JSON Payload

```json
{
  "notification": {
    "title": "New Order",
    "body": "Order #123 has been created"
  },
  "data": {
    "type": "order",
    "order_id": "123",
    "extra_field": "value"
  }
}
```

Supported types: `order`, `alert`, `system`, `chat`, `payment`, `ticket`, `ads`, `marketing`, `general`.

## 3. Remote Config (`RemoteConfigService`)

Permanent GetX singleton for reading **Firebase Remote Config**.

### Initialization

```dart
final rc = Get.put(RemoteConfigService(), permanent: true);
await rc.init();
```

### Default Keys

| Key | Type | Default | Description |
|---|---|---|---|
| `maintenance_mode` | `bool` | `false` | Is the app in maintenance |
| `maintenance_message` | `String` | `"The application is currently..."` | Maintenance message |

### Usage

```dart
final rc = Get.find<RemoteConfigService>();

// Check maintenance mode (reactive)
Obx(() {
  if (rc.maintenanceMode.value) {
    return MaintenancePage(message: rc.maintenanceMessage.value);
  }
  return HomePage();
});

// Custom key
final featureEnabled = rc.getBool('new_feature_enabled');
final apiVersion = rc.getString('api_version');
```

### Real-time Update

The service automatically listens to `onConfigUpdated` — if there's an update in the Firebase Console, the value will be synced without needing to restart the app.

## Initial Setup

1. Run FlutterFire CLI:
   ```bash
   flutterfire configure
   ```
2. Ensure `google-services.json` (Android) and `GoogleService-Info.plist` (iOS) are present
3. Set environment variables in `.env` if necessary

## Provisioning per Environment

### How Firebase is configured in this repo

There are TWO sources of Firebase configuration — both are per-env:

| Source | Role | Value Source |
|---|---|---|
| `.env` (`FIREBASE_*`, `ANDROID_FIREBASE_*`, `IOS_FIREBASE_*`) | `DefaultFirebaseOptions` (`lib/config/firebase/firebase_options.dart`) reads `Domain.firebase*` during `FirebaseService.init()` | One `.env` file with suffixes `_DEV` / `_STAGING` / `_PROD` — follows runtime env switching |
| `google-services.json` + `GoogleService-Info.plist` | Native config read by the Firebase plugin on the Android/iOS build side | Separate file per Firebase project — **gitignored, do not commit** |

Because env switching runs at runtime, Dart-side options are always consistent with the active env.
Native files only contain ONE set of configs per build — for multi-env native, provision the appropriate file before building, or separate them by flavor/scheme later.

### Local Provisioning

```bash
# From Firebase Console → Project Settings → Your apps:
#   Android → download google-services.json  → android/app/src/
#   iOS     → download GoogleService-Info.plist → ios/Runner/
```

Both files are already in `.gitignore`. CI runs the `secret-guard` job which fails the build
if these files (or `.env` / keystore) are tracked.

### Provisioning via CI (GitHub Actions secrets)

Store the files per environment as secrets (base64), then decode them in the workflow before building:

```bash
# Store once (locally):
base64 -i google-services.json | pbcopy          # → secret FIREBASE_ANDROID_JSON_DEV
base64 -i GoogleService-Info.plist | pbcopy      # → secret FIREBASE_IOS_PLIST_DEV
```

```yaml
# .github/workflows/build.yml
- name: Decode Firebase config (dev)
  env:
    FIREBASE_ANDROID_JSON: ${{ secrets.FIREBASE_ANDROID_JSON_DEV }}
    FIREBASE_IOS_PLIST: ${{ secrets.FIREBASE_IOS_PLIST_DEV }}
  run: |
    echo "$FIREBASE_ANDROID_JSON" | base64 --decode > android/app/src/google-services.json
    echo "$FIREBASE_IOS_PLIST" | base64 --decode > ios/Runner/GoogleService-Info.plist
```

### Security

- **Key restriction**: restrict Android keys to package name + SHA-1, iOS keys to bundle ID
  (Google Cloud Console → APIs & Services → Credentials). Client-side Firebase API keys
  are public by design — restrictions make them secure.
- **Do not commit** the production Firebase project to a public boilerplate — use a dummy
  project for example files.
