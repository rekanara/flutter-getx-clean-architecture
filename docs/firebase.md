# Firebase Services

Lokasi: `lib/config/firebase/`

## Struktur File

| File | Fungsi |
|---|---|
| `firebase_service.dart` | Inisialisasi Firebase Core |
| `firebase_options.dart` | Platform-specific config (generated by FlutterFire CLI) |
| `firebase_messaging_service.dart` | FCM: push notification, token management |
| `remote_config_service.dart` | Remote Config: maintenance mode, feature flags |

---

## 1. Firebase Core (`FirebaseService`)

Singleton static class — panggil sekali di `main.dart`:

```dart
await FirebaseService.init();
```

Otomatis membaca `DefaultFirebaseOptions.currentPlatform` yang dihasilkan oleh FlutterFire CLI.

---

## 2. Firebase Messaging (`FirebaseMessagingService`)

Permanent GetX singleton yang mengelola **FCM (push notification)**.

### Inisialisasi

```dart
final fcm = Get.put(FirebaseMessagingService(), permanent: true);
await fcm.init();
```

### Fitur

- **Permission request** (iOS) — otomatis di `init()`
- **Token management** — `fcmToken` observable, auto-refresh
- **APNs token** — untuk iOS
- **Foreground/Background/Terminated messages**
- **Topic subscribe/unsubscribe**
- **Routing berdasarkan `type`** dari JSON payload

### Cara Pakai

```dart
final fcm = Get.find<FirebaseMessagingService>();

// Baca token
print(fcm.fcmToken.value); // kirim ke backend

// Subscribe ke topic
fcm.subscribeToTopic('promo');
fcm.unsubscribeFromTopic('promo');

// Force refresh token
final newToken = await fcm.refreshToken();
```

### Alur Notifikasi Masuk

```
Push Notification Masuk
    │
    ├─ Foreground  → _processMessage() → ShowNotificationHelper
    ├─ Background  → firebaseMessagingBackgroundHandler (top-level)
    └─ Terminated  → _checkInitialMessage() → _handleNotificationTap()
    
_processMessage():
    1. Parse title, body dari message.notification
    2. Parse JSON dari message.data
    3. Ambil field "type" → _parseNotificationType()
    4. Panggil ShowNotificationHelper.showNotification()
```

### Payload JSON yang Diexpect

```json
{
  "notification": {
    "title": "Pesanan Baru",
    "body": "Pesanan #123 telah dibuat"
  },
  "data": {
    "type": "order",
    "order_id": "123",
    "extra_field": "value"
  }
}
```

Type yang didukung: `order`, `alert`, `system`, `chat`, `payment`, `ticket`, `ads`, `marketing`, `general`.

## 3. Remote Config (`RemoteConfigService`)

Permanent GetX singleton untuk membaca **Firebase Remote Config**.

### Inisialisasi

```dart
final rc = Get.put(RemoteConfigService(), permanent: true);
await rc.init();
```

### Default Keys

| Key | Type | Default | Deskripsi |
|---|---|---|---|
| `maintenance_mode` | `bool` | `false` | Apakah app dalam maintenance |
| `maintenance_message` | `String` | `"Aplikasi sedang..."` | Pesan maintenance |

### Cara Pakai

```dart
final rc = Get.find<RemoteConfigService>();

// Cek maintenance mode (reactive)
Obx(() {
  if (rc.maintenanceMode.value) {
    return MaintenancePage(message: rc.maintenanceMessage.value);
  }
  return HomePage();
});

// Custom key
final featureEnabled = rc.getBool('new_feature_enabled');
final apiVersion = rc.getString('api_version');
```

### Real-time Update

Service otomatis listen ke `onConfigUpdated` — jika ada update di Firebase Console, value akan ter-sync tanpa perlu restart app.

## Setup Awal

1. Jalankan FlutterFire CLI:
   ```bash
   flutterfire configure
   ```
2. Pastikan `google-services.json` (Android) dan `GoogleService-Info.plist` (iOS) sudah ada
3. Set environment variables di `.env` jika diperlukan

## Provisioning per Environment

### Bagaimana Firebase dikonfigurasi di repo ini

Ada DUA sumber konfigurasi Firebase — keduanya per-env:

| Sumber | Peran | Sumber Value |
|---|---|---|
| `.env` (`FIREBASE_*`, `ANDROID_FIREBASE_*`, `IOS_FIREBASE_*`) | `DefaultFirebaseOptions` (`lib/config/firebase/firebase_options.dart`) membaca `Domain.firebase*` saat `FirebaseService.init()` | Satu file `.env` dengan suffix `_DEV` / `_STAGING` / `_PROD` — mengikuti runtime env switching |
| `google-services.json` + `GoogleService-Info.plist` | Config native yang dibaca plugin Firebase di sisi Android/iOS build | File terpisah per project Firebase — **gitignored, jangan commit** |

Karena env switching berjalan di runtime, Dart-side options selalu konsisten dengan env aktif.
File native hanya berisi SATU set config per build — untuk multi-env native, provision file
yang sesuai sebelum build, atau pisahkan per flavor/scheme di kemudian hari.

### Provisioning lokal

```bash
# Dari Firebase Console → Project Settings → Your apps:
#   Android → download google-services.json  → android/app/src/
#   iOS     → download GoogleService-Info.plist → ios/Runner/
```

Kedua file sudah di-`.gitignore`. CI menjalankan `secret-guard` job yang mem-fail build
bila file ini (atau `.env` / keystore) ikut ter-track.

### Provisioning via CI (GitHub Actions secrets)

Simpan file per environment sebagai secret (base64), lalu decode di workflow sebelum build:

```bash
# Simpan sekali (locally):
base64 -i google-services.json | pbcopy          # → secret FIREBASE_ANDROID_JSON_DEV
base64 -i GoogleService-Info.plist | pbcopy      # → secret FIREBASE_IOS_PLIST_DEV
```

```yaml
# .github/workflows/build.yml
- name: Decode Firebase config (dev)
  env:
    FIREBASE_ANDROID_JSON: ${{ secrets.FIREBASE_ANDROID_JSON_DEV }}
    FIREBASE_IOS_PLIST: ${{ secrets.FIREBASE_IOS_PLIST_DEV }}
  run: |
    echo "$FIREBASE_ANDROID_JSON" | base64 --decode > android/app/src/google-services.json
    echo "$FIREBASE_IOS_PLIST" | base64 --decode > ios/Runner/GoogleService-Info.plist
```

### Keamanan

- **Key restriction**: batasi Android key ke package name + SHA-1, iOS key ke bundle ID
  (Google Cloud Console → APIs & Services → Credentials). API key Firebase client-side
  memang publik by design — restriction yang membuatnya aman.
- **Jangan commit** project Firebase production ke boilerplate publik — gunakan
  project dummy untuk file contoh.
